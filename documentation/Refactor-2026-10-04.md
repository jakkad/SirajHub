# Refactor notes — October 4, 2026

This is a focused maintenance pass across the Worker, frontend data lifecycle, build configuration, and dependencies. No database migrations or production deployment are included.

## Security and reliability

- Article, Goodreads, and cover fetching share `worker/src/lib/public-fetch.ts`. It accepts public HTTP(S) URLs, rejects credentials, nonstandard ports, local names and private/reserved IPv4 literals, checks each redirect, limits redirects to three, and uses a 15-second deadline. Actual response bytes are limited to 5 MiB for pages and 10 MiB for covers, even without an accurate Content-Length.
- This URL policy is defense in depth, **not DNS pinning**. Domains resolving to private addresses still require deployment-level egress protection. IPv6 literals are conservatively rejected. Large pages/images and nonstandard ports now intentionally fail.
- API requests are capped at 10 MiB. Mutations with an untrusted Origin (or cross-site browser metadata without an Origin) receive 403. Same-origin requests and local-to-local development requests remain supported; non-browser requests without Origin still require normal authentication. CORS uses the same origin policy.
- API responses default to `no-store` and `nosniff`; the authenticated cover endpoint retains its private image cache policy.
- React Query clients are scoped to the signed-in user and discarded on logout/account changes, preventing a later account from reusing the previous account's library/settings cache.
- Password helpers were extracted and now reject malformed hashes and excessive iteration counts without throwing. The existing PBKDF2 format, normalization, and work factor are preserved so existing accounts remain compatible. This does not upgrade password work factors or add account recovery.
- AI jobs use a conditional update with RETURNING to claim only still-queued, due jobs. Losing contenders skip execution instead of processing the same job concurrently. Recovery of jobs stranded by a terminated Worker is a separate remaining task.
- Metadata routing matches parsed provider hostnames instead of arbitrary URL substrings. Corrupt metadata cache entries are refreshed, and explicitly requested content types cannot reuse a different type's cached result.

## Performance and readability

- Route components are split into separate chunks. Capture and search dialogs are mounted only when opened, so their code and queries no longer load on every authenticated page.
- Import queue settings are read once per import instead of once per created row. Metadata cache hits avoid loading provider settings. Score synchronization no longer rereads each item immediately after updating its known score fields.
- Item mutations invalidate dependent lists, recommendations, reminders, and duplicate results as well as the item collection, preventing stale views after edits or deletion.
- Shared URL/password helpers replace inline implementations. Removed the placeholder production CORS list, an unused import, a no-op status branch, and a redundant CSV date expression. Historical documentation and applied migrations remain intact because they are useful records, not executable legacy code.

The measured main frontend entry chunk fell from **694.30 kB to 517.33 kB** (25.5% smaller), or **203.41 kB to 163.75 kB gzip**. These are bundle-size measurements, not measured page-load latency. Vite still warns that this entry exceeds 500 kB; third-party Zod annotation warnings are also non-fatal. The upgraded authentication dependency increased the Worker bundle from about 1.68 MB to 1.90 MB uncompressed.

## Verification

- `pnpm typecheck` checks both applications.
- `pnpm test` passes 10 tests using Node's built-in regression tests (Node 24, matching CI). Tests cover URL bypasses, redirects, response limits, request origins, password compatibility, and provider detection.
- `pnpm build` validates and bundles the Worker and frontend. In restricted environments, set `WRANGLER_LOG_PATH=/tmp/sirajhub-build.log` to keep Wrangler logs in a writable location.
- The deployment workflow runs type checks and regression tests before building.
- Local integration checks exercised sign-up, session lookup, settings, item create/list/update/delete, rejection of a cross-origin edit, sign-out, revoked-session access, and password sign-in. Temporary test users were removed afterward. The login page and unauthenticated redirect were checked in the browser.
- The final full `pnpm audit` (including development tooling) reports **zero known vulnerabilities** as of this run. A dependency audit prompted updates to authentication, HTTP, database, routing, and development tooling. The targeted `@esbuild-kit/core-utils>esbuild` override replaces the deprecated Drizzle tooling loader's vulnerable esbuild version; remove it when that upstream loader is retired. `drizzle-kit --version` was also checked. No remote provider calls or production load tests were performed.

## Follow-up engineering

1. Move queue processing out of synchronous read requests into a dedicated queue consumer with leases, execution deadlines, stale-job recovery, and idempotency keys. Simply moving the current loop into `waitUntil` risks leaving jobs processing when the post-response execution window ends.
2. Add pagination and database-backed search for large libraries; measure query counts and latency with realistic import sizes before restructuring imports.
3. Apply consistent runtime schemas to every route and import row, with field-specific validation errors. TypeScript request types alone are not runtime validation.
4. Add browser regression coverage for account switching, imports, dialogs, and list operations, and provider fixtures for remote metadata fetches.
5. Review encryption of stored personal provider keys, distributed abuse limits, account recovery, and password work-factor upgrades as dedicated security changes.

## Features to consider next

1. **Trash and undo:** soft-delete items with a recovery window, including bulk actions. This addresses the current permanent-delete workflow directly.
2. **Complete backup and restore:** a versioned export of items, tags, lists, notes, views, and preferences, with an import preview and duplicate reconciliation. Exclude credentials by default.
3. **Quick capture:** a browser extension or bookmarklet plus a mobile share target, reusing the existing ingest and duplicate APIs.
4. **Time-budget recommendations:** suggest something that fits 15, 30, or 60 minutes, combined with media type, mood, and the existing interest profile.
5. **Review and learning history:** weekly consumption summaries, resurfaced highlights, and progress trends so saved material turns into useful recall.
